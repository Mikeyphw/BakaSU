# GAP-02 — historical module ZIP discovery and compatibility

Reinstall prefers an exact installed `versionCode` from a fresh configured KernelSU registry when the offered update ZIP uniquely anchors that registry's immutable release roster. The selected historical release must belong to the same GitHub project and match its own tag, SHA-256, size and version. Ambiguous, stale, mutable or unavailable records cannot supply historical evidence. An unavailable historical candidate does not authorize a downgrade: the existing separately disclosed latest-version reinstall remains available through its existing verification and explicit confirmation route. A previously selected historical candidate is freshly resolved again before flashing; it may never degrade to the legacy route. The installed module ID, directory identity, version and enabled state are checked before flash, and the private archive copy must match the selected archive's module ID and version code as well as the expected registry digest and size when present.

For both stable and beta manager channels, the candidate must be an exact F07 fork APK. The GitHub asset size and digest bind both compatibility and F07 provenance documents, and the selected candidate's exact version, name, ABI, digest and size must agree with the reviewed provenance. The installed certificate must match the reviewed signer, and the downloaded APK must independently match that signer and the installed package. The APK's native library ABI roster is verified against the selected ABI and the device, including RISC-V in universal archives; no direct RISC-V publication path is introduced. Existing runtime kernel UAPI/KernelSU checks remain fail-closed on unknown or incompatible evidence. No change to root authorization or release publication policy is included.

`python3 -B scripts/fork/gap02_policy_probe.py` compiles the production dependency-free Kotlin policies using the Kotlin CLI and Java, then executes positive and negative behavioral tests. The hosted manager qualification invokes this probe before existing Gradle/Spotless/build checks. Full Android compilation, hosted source checks, actual signed release and installed-device tests remain separately required. No local Gradle, flash, release or signing is performed by this qualification.
